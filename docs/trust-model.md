# Модель доверия

Исполнитель, ревьюер и пользователь не заменяют друг друга.

- Инструментальная проверка подтверждается командой и реальным кодом выхода.
- Человеческое подтверждение записывается отдельно как `human_confirmed`.
- Невыполненная проверка остаётся `not_checked`. Из тишины не следует PASS.
- Вердикт подписывает ревьюер. Исполнитель не может выдать READY на собственную работу тем, что приложил отчёт.
- READY действует только для полного `reviewed_head_sha`. Следующий коммит требует нового разбора, даже если ветка и номер pull request те же.
- Спорное расхождение решает пользователь. Протокол не считает молчание пользователя разрешением на merge.

Непросмотренная ревизия протокола может содержать изменённые скрипты. Синхронизация поэтому отделяет данные от кода: текст правил и схемы можно прочитать, а новые скрипты не исполняются, пока эта ревизия сама не станет закреплённой и доступной для разбора. Следующий цикл синхронизации уже может использовать скрипты из принятого pin.

Адаптер Perplexity не создаёт канал управления. Это документ, который человек может вставить в сессию. Наличие файла в репозитории не означает, что разбор состоялся.
