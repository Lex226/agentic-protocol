# Границы

## Адаптеры

Общие правила живут в `protocol/` и попадают в адаптеры только через `scripts/generate-adapters.mjs`. Вручную те же правила в нескольких файлах не поддерживаются.

Генератор пишет только:

- `.cursor/rules/agentic.mdc`
- `.agentic/reviewer-context.md`
- `.agentic/handoff/executor-to-reviewer.md`
- `.agentic/handoff/reviewer-to-executor.md`

`AGENTS.md` и любые другие правила Cursor генератор не меняет. Если целевой файл уже существует и не помечен как созданный генератором, генератор останавливается и не записывает ни один файл.

`reviewer-context.md` — переносимый документ. Его передаёт человек. Perplexity не читает этот файл из репозитория автоматически и не запускается из него.

В каждом сгенерированном файле есть `protocol_version` и полный `source_sha` того коммита протокола, из которого собраны правила.

## Синхронизация

Workflow синхронизации может обновить закреплённый SHA и заново собрать адаптеры. Он не пушит в default branch напрямую и не включает automerge.

Новый коммит протокола читается как данные: `protocol/`, `schemas/`, `templates/`. Скрипты из ещё не принятой ревизии не запускаются. Генератор, который собирает адаптеры, берётся из уже закреплённой и доступной для разбора ревизии.

Если закреплённый SHA не является предком целевого коммита default branch, workflow не открывает pull request.

Нет содержательной разницы — нет нового коммита и нет нового pull request. Повторный запуск обновляет уже открытый pull request той же ветки, а не создаёт второй.

В репозитории и в отчётах не размещаются секреты и токены. Workflow просит только `contents: write` и `pull-requests: write`. Если `GITHUB_TOKEN` не может открыть pull request, в журнале указывается нужная настройка репозитория; личный токен для этого не запрашивается.
