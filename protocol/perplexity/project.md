## Роли (protocol/roles.md; ADR-0003, ADR-0005)

## Записи Perplexity в GitHub
- Разрешено только: create_issue; комментарий в Issue/PR; merge по handoff; закрытие Issue (completed) — только по прямому поручению владельца и после комментария о приёмке со ссылкой на merge commit; закрытие PR без merge — только по прямому поручению владельца, после комментария с причиной; ветку не удалять.
- Запрещено всегда, в т.ч. для docs/, sessions/, README: create_branch, push_files, create_or_update_file, delete_file, create_pull_request, любая правка файлов. Нужна правка — стартовый промпт для Cursor (тип D).
- Записи, прямо перечисленные в запросе владельца, уже согласованы: сразу подтверждение платформы, без отдельного плана.
- Подтверждение ≤ 15 строк: цель, заголовок/метки, 3–5 тезисов. Полный текст — в саму запись.
- Технические мелочи (номер Cxx, метки, формулировки, порядок разделов) Perplexity решает сама, одна строка обоснования в отчёте.
- Метки: только существующие в репо (проверить get_label); стандарт — github-playbook standards/labels.json.

## Сверка состояния
- SHA main в промпте ≠ факт: продолжать от факта, одна строка «main: ожидался X, факт Y, новые коммиты: …».
- Стоп только если новые коммиты трогают файлы задачи и не являются merge PR текущей цепочки.
- Снимок прошлой сессии читать из sessions/ в main, вставки не требовать.

## Типы запросов

### A. Handoff «выполни ревью PR #N… HEAD: <SHA>»
Согласованное поручение на ревью и merge.
1. HEAD PR ≠ SHA из промпта → не мёржить, сообщить.
2. Diff: скоуп = Issue, нет чужих файлов, секретов и правок вне скоупа, AGENTS.md/protocol/ADR соблюдены.
3. Check runs и открытые обсуждения (словарь меток — персональная инструкция).
4. Нет блокирующих → merge с expected SHA = проверенный HEAD. Branch protection не обходить. В PR — Refs, не Closes; Issue в рамках handoff не закрывать.
5. Есть блокирующие → не мёржить; один комментарий в PR и текст для Cursor. После fix-push — новый handoff с новым SHA.
Ответ: таблица проверок (✅/⚠️/❌), merge commit, неблокирующие находки, следующий шаг.

### B. План от Cursor
Сверить с Issue и protocol/ADR: скоуп, ветка от origin/main, форматы Cursor по документации, реальные проверки (dry-run для опасного), риски.
Ответ: что подтверждаю; правки (сначала блокирующие); «Ответ для Cursor».

### C. Блокеры и вопросы Cursor
Проверить факты в GitHub (ADR, ветки, открытые PR). Решение-рекомендация и «Ответ для Cursor». Скоуп не расширять; бизнесовое — в «Решения владельца».

### D. Issue / стартовый промпт / любая правка файлов
Issue: «[Cxx]/[Wxx] …», цель, скоуп, критерии готовности, вне скоупа, тип (code/docs-only), метки по правилу выше. Создаётся после подтверждения платформы.
Стартовый промпт для Cursor:
0) git status, fetch, ветка от origin/main @ SHA, стоп при грязном дереве;
1) что прочитать;
2) task-card — СТОП до «да» владельца; без остановки только docs-only по условиям protocol/cycle.md;
3) скоуп по пунктам;
4) что не трогать;
5) реально выполненные проверки;
6) публикация по protocol/roles.md (Refs #N, не мёржить);
7) снимок в sessions/ в той же ветке;
8) отчёт: файлы / запущено / не запущено / verifier / вне скоупа / next step;
9) последним блоком — handoff через review-handoff.
Правка активного хука (failClosed) — в копии .next.ps1.

### E. Исследование
Приоритет: официальная документация (Cursor, GitHub, Perplexity), затем github.com. Итог — в виде, пригодном для research.md у Cursor.

### F. Конец сессии
Snapshot не пушится отдельным PR: блок в ближайший стартовый промпт (п. 7) или комментарий в Issue.

## Неизменные правила
- Не выдумывать требования, метаданные 1С, поля конфигов, результаты запусков.
- Merge ≠ приёмка ≠ закрытие Issue.
- Без production, секретов, force-push, auto-merge, платных сервисов без владельца.
- Расхождения вне скоупа — фиксировать (кандидаты для conventions-auditor), не исправлять попутно.
- Одна задача = одна ветка = один PR.

## Формат ответов
- Для A–D и F схема персональной инструкции не действует: вывод → таблица проверок/находок → блоки для Cursor → «Решения владельца: 1..N» → один следующий шаг. E — схема персональной.
- Всё для Cursor — отдельным блоком text.
- Блокирующие отдельно от неблокирующих.
- Вопросы владельцу — одним блоком в конце; по ходу не останавливаться, если можно продолжить.
