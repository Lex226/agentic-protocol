# Цикл

Согласованная задача проходит так:

1. Рабочая ветка от обновлённого `main`.
2. Изменения в границах задачи.
3. Снимок сессии.
4. Проверки, которые реально доступны.
5. Verifier: родитель собирает пакет и передаёт его субагенту. Если субагент недоступен, в отчёте и handoff пишется `verifier (субагент): не запущено` с причиной. Сверка родителем не подставляется и так не называется.
6. Commit, в который входит снимок.
7. Push рабочей ветки.
8. Pull request.
9. Промпт handoff с полным SHA.
10. Независимое ревью Perplexity.
11. Merge только проверенного SHA.

Задача из брифа Perplexity начинается скиллом `task-start`.

## Рабочий каталог

Задачи идут последовательно в основном checkout. Параллельная задача ведётся только в отдельном клоне `../<repo>-<cxx>`, одно окно Cursor на клон.

Ветка задачи существует только в одном клоне. До создания ветки выполняется `git ls-remote --heads origin <branch>`. Непустой ответ — СТОП.

Клон удаляется только после merge, при чистом `git status` и пустом `git log origin/<branch>..HEAD`.

На старте дерево чистое: `git status` без правок.

Перед сбором пакета verifier нет неиндексированных правок и неотслеживаемых файлов — все правки задачи в индексе (`has_unstaged_changes: no`). Если `has_unstaged_changes: yes`, родитель останавливается и не передаёт этот пакет субагенту. Дерево приводится к staged-набору, пакет собирается заново.

СТОП относится к пакету, который передаётся субагенту. Правка снимка после прогона verifier индексируется заново перед commit; пакет повторно не собирается; в снимке пометка «дописано после прогона».

Verifier — предварительная сверка на стороне Cursor. Он не заменяет ревью и merge из `protocol/roles.md`. Родитель собирает пакет командой `scripts/verify/collect-verifier-pack.ps1`. Субагент читает пакет и перечисленные файлы и не запускает git. С параметром `-Issue` и origin на GitHub в пакет входят заголовок и тело Issue; ошибка `gh` останавливает сбор. Без GitHub-origin `gh` не вызывается, в секции скоупа остаётся заглушка.

Если ревью оставило замечания, исправление — новый commit в ту же ветку, push и новый handoff. Предыдущий промпт недействителен.

## Исключение docs-only

Если выполнены все условия ниже, Cursor выводит карточку и продолжает без остановки на «да».

Условия действуют все одновременно:

- тип в брифе — `docs-only`;
- скоуп по пунктам (файл, место, что меняется) задан владельцем в Issue или брифе;
- меняются только `*.md` вне `.cursor/` и снимок сессии;
- не затрагиваются `scripts/`, `.cursor/`, `protocol/version.json`, LICENSE, теги и настройки GitHub;
- не меняются `protocol/roles.md`, `verdict.md` и `handoff.md`.

Нарушение любого условия, неясный пункт или новое требование — СТОП. Карточка выводится всегда. Проверки, снимок, PR, handoff и независимое ревью обязательны.

## Версия и релиз

Pull request, который меняет поведение движка, добавляет запись в раздел `## [Unreleased]` файла `CHANGELOG.md`.

Релизный pull request переименовывает `## [Unreleased]` в `## [<версия>]` и меняет `protocol/version.json` на эту версию.

Тег `v<версия>` и GitHub Release создаёт только workflow `release` на merge commit в `main`. Ручные теги и перенос тегов запрещены.

## Снимок сессии

В конце задачи Cursor создаёт `sessions/YYYY-MM-DD-slug.md`. При совпадении имени — новый slug. Frontmatter: `date`, `task`, `refs`, `author: Cursor`. Разделы: задача/ветка/commit, сделано, решения, проверки с результатами, блокеры, следующий шаг. Снимок не содержит секретов. Персональные данные — только если AGENTS.md потребителя содержит явное исключение с политикой данных и ссылкой на решение владельца (`protocol/precedence.md`); иначе запрещены. Он передаёт контекст между сессиями. Статус планирования живёт в Issues.
