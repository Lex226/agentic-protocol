# Цикл

Согласованная задача проходит так:

1. Рабочая ветка от обновлённого `main`.
2. Изменения в границах задачи.
3. Снимок сессии.
4. Проверки, которые реально доступны.
5. Verifier: родитель собирает пакет, субагент сверяет его со скоупом.
6. Commit, в который входит снимок.
7. Push рабочей ветки.
8. Pull request.
9. Промпт handoff с полным SHA.
10. Независимое ревью Perplexity.
11. Merge только проверенного SHA.

Задача из брифа Perplexity начинается скиллом `task-start`.

Verifier — предварительная сверка на стороне Cursor. Он не заменяет ревью и merge из `protocol/roles.md`. Родитель собирает пакет командой `scripts/verify/collect-verifier-pack.ps1`. Субагент читает пакет и перечисленные файлы и не запускает git. С параметром `-Issue` и origin на GitHub в пакет входят заголовок и тело Issue; ошибка `gh` останавливает сбор. Без GitHub-origin `gh` не вызывается, в секции скоупа остаётся заглушка.

Если ревью оставило замечания, исправление — новый commit в ту же ветку, push и новый handoff. Предыдущий промпт недействителен.

## Снимок сессии

В конце задачи Cursor создаёт `sessions/YYYY-MM-DD-slug.md`. При совпадении имени — новый slug. Frontmatter: `date`, `task`, `refs`, `author: Cursor`. Разделы: задача/ветка/commit, сделано, решения, проверки с результатами, блокеры, следующий шаг. Снимок не содержит секретов и персональных данных. Он передаёт контекст между сессиями. Статус планирования живёт в Issues.
