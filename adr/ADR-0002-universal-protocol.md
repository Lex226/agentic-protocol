# ADR-0002 — Универсальный протокол

Статус: Proposed

Согласование владельца на статус Accepted этим файлом не утверждается. Пока статус Proposed, поведение движка не меняется: `protocol/roles.md`, `protocol/cycle.md`, `protocol/platform.md`, `protocol/handoff.md` и `protocol/verdict.md` остаются в силе как написаны.

## Контекст

Issue #23 просит зафиксировать устройство универсального протокола: слои, манифест репозитория-потребителя, роли и развёртывание через Cursor. Нужны решение и структура, без кода.

Сейчас канон движка в этом репозитории — каталог `protocol/` и уже импортированные слои Cursor (субагент verifier, скиллы, guard). Каталога `adr/` на `main` до этого решения не было. Корневого `AGENTS.md` нет: для этого репозитория источник текста протокола — `protocol/`.

Пилот-потребитель `Lex226/1c-document-collection` хранит публикацию согласованной задачи в `adr/ADR-0003-agent-pr-workflow.md` и слои движка v0 в `adr/ADR-0005-cursor-engine.md` (чтение 10.11.2026). Здесь те же правила записаны в `protocol/`, а не в ADR. Этот ADR их не отменяет.

Первый адаптер роли уже лежит в `protocol/perplexity/`. Его README называет эти файлы источником истины для текста Space: правка идёт Issue → PR → merge, затем владелец вставляет текст в Space.

Правило 3 конституции `Lex226/github-playbook` `standards/00-constitution.md` (файл в локальном клоне, HEAD `eeffb66e9669e933dab0f1ea816a59d802f3055a`, чтение 10.11.2026) требует для ADR секции `## Контекст`, `## Принятое решение` и строку `Статус:`. Шаблон не удаляется и не используется как реальное решение. Шаблон этого репозитория — `adr/ADR-0001-template.md`, по форме шаблона пилота `1c-document-collection`. В `Lex226/1c-repo-template` (main `1481c514f576c2c8779829bc23a09c30ed0209a6`, чтение 10.11.2026) свой шаблон начинается со строки `Статус: active` и повторяет статус внизу. Значение `active` не входит в перечень Правила 3. Этот репозиторий ту строку не копирует.

## Принятое решение

### Решения владельца (10.11.2026)

1. Ревьюер может быть внутренним (агент в Cursor), merge тогда делает владелец. В правилах явно указать, что независимость ревью снижена, и перечислить риски.
2. Метки при развёртывании всегда ставит Cursor по манифесту.
3. W02 идёт параллельно с открытыми Issues.

Ниже — как эти три решения ложатся на слои. Они не переписывают текущие файлы `protocol/`.

### Слои

| Слой | Путь | Назначение |
|---|---|---|
| Ядро | `protocol/` | Роли, цикл, платформа, handoff, вердикт. Источник текста протокола в репозитории `agentic-protocol`. |
| Адаптеры ролей | `adapters/` | Привязка абстрактной роли к инструменту. Каталог этим ADR не создаётся. |
| Профили стека | `profiles/` | Набор под стек потребителя. Каталог этим ADR не создаётся. |
| Шаблоны | `templates/` | Заготовки файлов потребителя. Каталог этим ADR не создаётся. |
| Манифест потребителя | `.agentic/config.json` и `.agentic/lock.json` | Что развернуть и что уже применено. Файлы этим ADR не создаются. |

Слои движка v0 из ADR-0005 пилота (`.cursor/rules/`, `.cursor/agents/verifier.md`, `scripts/verify/collect-verifier-pack.ps1`, `.cursor/hooks.json` и guard, скиллы task-card и review-handoff) остаются. Этот ADR добавляет к ним слои протокола, а не заменяет v0.

### Роли и `reviewer.independence`

Роли: Owner, Implementer, Reviewer, Researcher.

| Роль | Инструмент при `external` | Что делает |
|---|---|---|
| Owner | человек-владелец | Продуктовые решения, скоуп, допуск, приёмка. |
| Implementer | Cursor | Правит файлы, проверки, verifier, commit, push, PR, handoff. Merge не делает, auto-merge не включает. |
| Reviewer | Perplexity | Независимое ревью опубликованного HEAD и merge, если нет блокирующих замечаний. |
| Researcher | Perplexity | Исследование, Issues, стартовые промпты. Во время реализации файлы не правит. |

Поле манифеста: `reviewer.independence` со значениями `external` или `internal`. Значение по умолчанию и единственное применимое сегодня — `external`. Оно совпадает с `protocol/roles.md`, шагом 10–11 `protocol/cycle.md`, фразой `protocol/platform.md` «merge в main делает только ревьюер» и с ADR-0003 / ADR-0005 пилота.

`internal` — ревьюер является агентом в Cursor, merge делает владелец. Вердикт такого ревью помечается дословно: «ревью внутреннее, независимость снижена». В текст вердикта входит список рисков и мер ниже.

Текущий `protocol/roles.md` этот режим не допускает: merge опубликованного HEAD делает Perplexity, Cursor merge не делает. Пока отдельная задача не изменит `protocol/roles.md`, значение `internal` в манифесте не применяется. Записывать его заранее можно только как намерение, не как действующее правило. Права C13 (#24) этим режимом не расширяются: #24 явно не даёт `roles.md` ничего сверх наката меток.

Риски `internal`:

- Ревьюер и исполнитель — агенты Cursor. Общие правила и происхождение в одном продукте снижают независимость по сравнению с Perplexity. Отдельное контекстное окно субагента (`.cursor/agents/`, [Subagents](https://cursor.com/docs/subagents), чтение 10.11.2026) изолирует контекст, но не создаёт вторую сторону и не заменяет ревью из `protocol/roles.md`.
- Отчёт исполнителя о тесте не равен независимому запуску (`protocol/verdict.md`). Внутренний агент может опереться на тот же отчёт.
- На базовой линии private / GitHub Free нет обязательных status checks (`protocol/platform.md`). Сервер не остановит merge владельца.
- Guard в `.cursor/hooks.json` — локальный контроль команд агента, в том числе через `beforeShellExecution` ([Hooks](https://cursor.com/docs/hooks), чтение 10.11.2026). Он не заменяет ревью и не заменяет защиту ветки. То же последствие зафиксировано в ADR-0005 пилота.
- Пометка вердикта не отменяет блокирующий дефект и не включает auto-merge.

Меры:

- Вердикт несёт фразу «ревью внутреннее, независимость снижена» и этот список рисков.
- Merge делает владелец, вручную, только для SHA из актуального handoff. Cursor по-прежнему не мёржит и auto-merge не включает.
- Отсутствие CI не считается успешным CI (`protocol/verdict.md`, `protocol/handoff.md`).
- Verifier остаётся предварительной сверкой Cursor и не называется независимым ревью (`protocol/cycle.md`, ADR-0005).
- До правки `protocol/roles.md` режим не используется.

Расхождение, которое та будущая правка обязана закрыть вместе с `roles.md`: `protocol/platform.md` сейчас говорит, что merge делает ревьюер, а шаг 10 `protocol/cycle.md` — что ревью независимое и его делает Perplexity. Если поменять только `roles.md`, эти две фразы останутся против `internal`. Это одна C-задача плана (C16), не этот PR и не #24.

Решение владельца 3: W02 идёт параллельно с открытыми Issues. Отдельная ветка и отдельный PR, без ожидания C10, C11 и C09 и без правки их файлов. Правило «одна задача — одна ветка — один PR» сохраняется.

### Метки

Решение владельца 2 действует как цель развёртывания: метки при развёртывании всегда ставит Cursor по манифесту. Накат только аддитивный: отсутствующие метки набора создаются, цвет и описание существующих в наборе обновляются, метки репозитория вне набора не удаляются.

Поля манифеста, которые ждёт C13 (Issue #24), фиксируются здесь и не заменяются:

- `labels.source` — репозиторий набора. Первое значение: `Lex226/github-playbook`. Файл набора внутри него — `standards/labels.json` (Правило 5 конституции). Отдельного поля пути нет.
- `labels.ref` — полный SHA коммита `labels.source`, на котором читается `standards/labels.json`. Это вход `-LabelsRef` из скоупа #24.

Путь скрипта в движке: каталог `scripts/labels/`, файл `scripts/labels/apply-labels.ps1`. Исходник переноса — `scripts/apply-labels.ps1` в github-playbook; состав переноса и отказ от `-RemoveExtra` описаны в #24. Прочитанный скрипт playbook (тот же HEAD `eeffb66`, 10.11.2026) удаляет лишние метки только при `-RemoveExtra`. Целевое поведение движка — без удаления. Пока C13 не смёржен, в `protocol/roles.md` разрешения накатывать метки нет, и этот ADR его не добавляет.

После merge этого PR #24 менять не нужно: путь и имена полей совпали с ожиданием в теле #24. Если бы имена были другими, скоуп #24 правился бы комментарием до старта реализации. Статус Proposed на это указание не влияет: #24 само называет старт после merge W02.

Набор `standards/labels.json` в движок не переносится.

### Развёртывание

Скилл `protocol-init` задаёт вопросы и пишет манифест потребителя. Скилла в репозитории ещё нет; этот ADR его не добавляет (`.cursor/` не меняется). Когда его добавят, это каталог `.cursor/skills/protocol-init/SKILL.md`: Cursor поднимает скиллы из `.cursor/skills/` и `.agents/skills/`, файл `SKILL.md` с полями `name` и `description`, агент подключает скилл по описанию ([Agent Skills](https://cursor.com/docs/skills), чтение 10.11.2026). Пример на той же странице прямо говорит спросить пользователя, если не хватает данных. Список вопросов не шире уже названных полей: `reviewer.independence`, `labels.source`, `labels.ref`, какие адаптер и профиль копировать.

Дальше детерминированный скрипт копирует файлы по манифесту. Путь скрипта этот ADR не назначает: его назовёт задача реализации. Модель не переписывает скопированный текст протокола свободно.

В `AGENTS.md` потребителя модель пишет свободно только раздел «О репозитории». Остальные разделы этого файла даёт генерация при развёртывании. Это правило протокола. Прочитанные страницы Cursor не описывают замок на отдельный раздел markdown: `AGENTS.md` — обычный markdown в корне и во вложенных каталогах ([Rules](https://cursor.com/docs/rules), чтение 10.11.2026). Удержание границы — инструкция скилла и то, что прочие файлы кладёт скрипт.

Правила проекта Cursor, если потребитель их получит, остаются файлами `.mdc` в `.cursor/rules` с `description`, `globs` и `alwaysApply` ([Rules](https://cursor.com/docs/rules), чтение 10.11.2026). Та же страница разрешает `.mdc` внутри подкаталога и игнорирует plain `.md` в `.cursor/rules`. `standards/11-cursor-conventions.md` (чтение 10.11.2026) требует плоские `.mdc` и запрещает `.cursor/rules/<name>/RULE.md` как формат, который в проверке playbook не читался. Запрет `RULE.md` — правило playbook. Этот ADR playbook не меняет и формат rules не выбирает заново.

Страница Rules также пишет, что правила сами из чужого репозитория не импортируются: их везут плагином через marketplace. Это не механизм развёртывания протокола. `standards/11` отдельно запрещает Remote Rules (Add from GitHub) и оставляет раздачу тонкого скелета скрипту playbook. См. следующий раздел.

### Обновление потребителя

Новая версия протокола попадает в потребитель pull request'ом. Сверка — по `.agentic/lock.json`: что применено, против версии, которую несёт PR. Прямой push в `main` потребителя этим решением не разрешается. Точный список полей lock, кроме факта сверки, задаёт C14. Пока скрипта нет, подключение остаётся тем, что уже написано в `README.md`: ручное копирование состава с тега.

### `protocol/perplexity/` — первый адаптер

Каталог `protocol/perplexity/` — первый адаптер роли (Researcher и, при `external`, Reviewer). Текст остаётся на этом пути, пока задача плана не заведёт `adapters/` и не перенесёт или не обернёт каталог. Порядок «источник в main → владелец вставляет копию в Space» не меняется. Файлы `protocol/perplexity/` этот PR не правит.

### `1c-repo-template` и `scripts/sync-agent-rules.ps1`

Решение: оставить оба как есть. Не заменять их протоколом и не вызывать из развёртывания протокола.

Прочитано 10.11.2026:

- `Lex226/1c-repo-template` main `1481c514f576c2c8779829bc23a09c30ed0209a6`: `AGENTS.md` — скелет репозитория 1С (BSL, MXL, запрет расширений и прод-баз); `.cursor/rules/000-project-core.mdc` — короткое alwaysApply-правило «сначала читай AGENTS.md»; `scripts/setup-new-repo.md` после создания из template велит вручную запустить `github-playbook/scripts/apply-labels.ps1`. В дереве есть правила BSL и docs. Это не универсальный манифест.
- `Lex226/github-playbook` `scripts/sync-agent-rules.ps1` (локальный клон, HEAD `eeffb66e9669e933dab0f1ea816a59d802f3055a`): по умолчанию источник `Lex226/1c-repo-template`, копируемые пути только `AGENTS.md` и `.cursor/rules/000-project-core.mdc`, чтение через `gh api`. Прочитанный текст показывает diff и заканчивает dry-run без push.
- `standards/11-cursor-conventions.md`: раздача правил идёт через этот template и этот скрипт, не через Remote Rules.

Замена смешала бы скелет 1С с движком. Использование скрипта как установщика протокола положило бы 1С-шный `AGENTS.md` поверх `AGENTS.md` потребителя и затёрло бы границу «свободно только „О репозитории“». Чек-лист template по-прежнему указывает на скрипт меток в playbook. Обновление чужого репозитория сюда не входит. Пометка deprecated копии скрипта меток в playbook — отдельная задача playbook после merge C13, как уже написано в #24.

### `AGENTS.md`

В потребителе `AGENTS.md` генерируется при развёртывании. В `agentic-protocol` файл не генерируется: источник — `protocol/`. Приоритет вложенного `AGENTS.md` над корневым, если оба есть, описан на [Rules](https://cursor.com/docs/rules) (чтение 10.11.2026) и в Правиле 11 конституции. Генерация не отменяет этот приоритет: она создаёт корневой файл потребителя и не подменяет ближайший вложенный.

## Альтернативы

Сделать `internal` действующим правилом в этом PR — отклонено. `protocol/roles.md` режим не допускает, а исключение docs-only запрещает править `roles.md`, `verdict.md` и `handoff.md`.

Назвать другие поля меток или другой путь скрипта — отклонено. #24 уже ждёт `scripts/labels/` и `labels.source` + `labels.ref`. Другие имена потребовали бы комментарий к #24 до старта.

Заменить `1c-repo-template` или поручить установку протокола `sync-agent-rules.ps1` — отклонено по чтению выше.

Считать verifier независимым ревьюером для `internal` — отклонено. Это уже отклонено в ADR-0005 и повторено в `protocol/cycle.md`.

Перенести `protocol/perplexity/` в этом PR — отклонено. Каталог `adapters/` вне скоупа, текст C12 не меняется.

## Последствия и проверка

Поведение движка не меняется. Запись в `CHANGELOG.md` не следует из `protocol/cycle.md`: pull request не меняет поведение. `protocol/version.json` не меняется.

Строка статуса в файле одна: `Статус: Proposed`. YAML-фронтматтер не используется. Перечень Правила 4 (`draft`, `hypothesis`, `tested`, `verified`, `deprecated`, `vendor-confirmed`) — про проверку содержания, не про жизненный цикл ADR. Два статуса в одном файле расходились бы.

Ручное копирование состава из `README.md` после строки про `adr/` включает эти два файла. Это следствие запрошенной строки раздела «Состав», не новый установщик.

Проверка решения — чтение этого файла против `protocol/roles.md`, `protocol/cycle.md`, `protocol/platform.md`, ADR-0003 и ADR-0005 пилота. Утверждения о текущем цикле должны совпадать с этими текстами. Утверждения о `internal` и о накате меток должны быть помечены как ещё не действующие.

Условие пересмотра: явное Accepted владельцем, либо merge C16, либо смена имён полей до старта #24. Непроверено и этим ADR не утверждается: что Cursor запирает раздел «О репозитории», что субагент равен независимому ревью, что dry-run `sync-agent-rules.ps1` когда-либо писал файлы в другой ревизии скрипта.
